# Agent Note：聊天消息正文的持久化批注

Status: proposed

[English](2026-11-21-chat-message-annotations.md) | 中文

## 问题

阅读聊天内容时，用户需要保留一小段上下文。文字选择工具栏可以复制选区，并把持久标记或私有说明附加到选中的文字上。浏览器 `Range` 只属于当前 DOM 实例，无法在 Markdown 重建、消息流式更新、虚拟列表回收或应用重启后继续作为身份使用。

## 方案

将批注存储为独立的 SQLite DataApi 资源，由主题和单条消息正文 part 共同拥有。每条记录保存可见文本投影中的 UTF-16 范围、选中文字和有界的前后文。消息 DOM 重建后，渲染器优先使用精确文本匹配，并使用前后文作为重定位回退。

聊天消息文字选择工具栏保留复制、引用和保存到笔记，并为符合条件的消息文本选区增加划线、想法和追问。划线没有内容，显示白色虚线。想法和追问必须填写内容。想法使用当前主题的 primary 颜色显示在线上，追问使用当前主题的半透明高亮显示。追问内容始终属于批注，不进入输入框、发送流程或模型执行流程。

批注控件只对完整位于单条聊天消息正文和单个文本 part 内的选区开放。现有系统级全局选区窗口以及跨消息选区不属于本功能。已有标记可以打开编辑内容或删除。标记通过 CSS Custom Highlight 挂载，并在虚拟列表重新挂载时清理生命周期并重新定位。

服务层在创建前校验主题归属、消息归属和角色一致性。主题和消息外键级联清理批注。渲染器 mutation 通过 DataApi 数据变更通知刷新主题批注查询。

## 已考虑的替代方案

- 将标记存入 localStorage 或 preference 会使其他窗口无法访问，并绕过应用备份和删除语义。
- 只保存 DOM range 会在 Markdown 或虚拟列表重建 DOM 时丢失批注。
- 将追问文本送入普通聊天输入框会把阅读批注变成未经请求的模型请求，违反已确认的行为。

## 后果

- 数据库增加持久化批注表，并追加一条迁移。
- 消息渲染需要提供稳定的消息和 part 元数据，用于捕获和恢复 anchor。
- 渲染器负责 anchor 投影、CSS Highlight 生命周期和小型编辑删除界面。主进程服务负责校验和持久化。
- anchor 绑定消息 part 的可见文本。大幅编辑删除选中文字时，批注可能暂时无法定位，直到文字恢复或用户删除批注。

## 风险

- 如果消息文本变化到精确文本和前后文都无法匹配，渲染器会暂时跳过该批注，直到文字恢复或用户删除批注。
- 视觉标记层依赖 CSS Custom Highlight。运行时不支持该能力时，持久化记录仍然保留，但不会显示视觉投影。
- 主题软删除时，服务层查询会隐藏批注。主题或消息硬删除时，数据库级级联会一并删除批注。
## 验收标准

- AC1 — 聊天消息工具栏保留复制、引用和保存到笔记，并对完整位于单条消息正文和单个文本 part 内的非空选区增加划线、想法和追问。跨消息选区、可编辑控件、思考或工具控件以及系统级选区窗口不会创建批注。（验证：渲染器单测和 Electron，聊天 UI 负责人）
- AC2 — 划线无需内容即可保存，并显示白色虚线。想法和追问必须填写非空内容，使用主题 token 显示，并在消息重载和应用重启后持久化。（验证：渲染器单测、服务单测和 Electron，聊天 UI 与数据负责人）
- AC3 — 每条保存的标记都保存包含 UTF-16 start/end、精确文本和有界前后文的消息 part anchor。Markdown 重建和虚拟列表卸载再挂载后，精确匹配和上下文重定位可以恢复标记。（验证：anchor 单测和 Electron，聊天 UI 负责人）
- AC4 — 点击已有标记会打开对应的编辑界面。想法和追问可以更新内容，所有批注类型都可以删除。（验证：渲染器单测和 Electron，聊天 UI 负责人）
- AC5 — DataApi 列表、创建、读取、更新和删除 handler 校验主题与消息归属，追加 `0042` 迁移，并在主题或消息被硬删除时清理批注。（验证：schema、迁移、handler 和 service 单测，数据负责人）
- AC6 — 保存追问不会填入聊天输入框、发送消息或启动模型执行。用户显式批量导入后，最新助手回复上的每条追问都会作为独立的原生引用 token 追加到现有草稿，使用 Cherry 自带的 blockquote 格式和消息气泡图标。每个引用都包含助手角色、轮次、消息序号和 ID、选区范围、助手原文片段及用户追问，且不会发送。（验证：渲染器单测和 Electron，聊天 UI 负责人）
- AC7 — 想法和追问编辑器在可用聊天工作区内居中打开，拖动时保持在工作区边界内，并提供参考 DSH 的可拖动/缩放框体、原文区域和输入区域；创建或打开标记时会展示 Home 批注侧栏并选中对应标记。（验证：渲染器测试和 Electron，聊天 UI 负责人）
- AC8 — 功能使用 i18n 文案、可访问控件和浅色/深色主题 token，不硬编码批注颜色。（验证：变更文件 lint 和双主题 Electron，聊天 UI 负责人）
- AC9 — Home 右侧栏默认打开批注面板。面板显示当前会话计数和唯一的最新追问导入按钮；条目使用分隔线、原始标记样式、批注内容和时间，并提供 DSH 风格的空状态。（验证：渲染器测试和 Electron，聊天 UI 负责人）
- AC10 — 导入的追问 token 悬浮时完整展示来源定位、原文片段和追问，并可滚动查看；删除图标不再显示原生悬浮提示。（验证：输入框 token 单测和 Electron，聊天 UI 负责人）

## 验证计划

运行 shared schema、service、migration、anchor、toolbar 和消息渲染的聚焦测试。运行变更文件的 typecheck 和 lint。使用受跟踪的 Electron 实例验证选区、持久化、虚拟列表回收、编辑、删除、浅色/深色主题以及追问没有发送副作用。

## 待决问题

无。用户确认的行为和所有权边界已固定用于本次实现。
